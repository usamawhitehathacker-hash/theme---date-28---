# Premium Header with Mega Menu Enhancements

This change adds seven premium features to the Shopify Horizon theme header: a top utility bar with contact/social links, shrink-on-scroll sticky behavior, a mega menu promotional block, menu item badges, four mega menu animation modes, a wishlist icon in header actions, and a mobile bottom navigation bar. All features are gated behind schema checkboxes and render conditionally.

**Watch for:** Mobile bottom nav relies on fragile DOM queries to trigger search and menu drawer (confirmed). Badge rendering is limited to the first menu item only, which may surprise merchants expecting per-item control (confirmed). The promo block always occupies 2 grid columns regardless of actual mega menu width, risking overflow on narrow menus (likely).

## High-level view

The top utility bar slots in as a new header row above the existing top/bottom rows, inheriting the section's color scheme system. It receives all data as render parameters from the header section schema.

Shrink-on-scroll adds a third sticky mode alongside "always" and "scroll-up". The JavaScript toggles a `data-shrink-state` attribute at a fixed 50px scroll threshold with no hysteresis, meaning rapid toggling is possible near the boundary.

The mega menu promo block renders as the rightmost 2 columns in the mega menu grid. When the promo is enabled alongside featured products or collections, total column demand may exceed the grid's configured column count, producing unpredictable layout.

Menu item badges are hard-coded to appear only on `forloop.first`, meaning only the first nav item gets a badge regardless of which item the merchant intends to highlight. The schema exposes badge settings at the block level without documenting this limitation.

Mega menu animations are purely CSS-driven via a `data-animation` attribute. The non-default modes (fade, slide-down, scale-up) set `clip-path: none`, which breaks synchronization with the header's underlay height animation — the shadow/background reveal won't match the content transition.

The wishlist icon follows the existing header-actions pattern but introduces a hard-coded fallback URL (`/pages/wishlist`) that will 404 on stores without a matching page.

The mobile bottom nav triggers search and menu drawer by querying the DOM for specific selectors and calling `.click()`. If the header drawer or search component's markup changes, the bottom nav breaks silently with no error feedback.

<summary>Issues (7)</summary>

1. **Mobile bottom nav DOM coupling** — `openSearch()` and `openMenu()` find targets via CSS selectors like `.header__drawer details summary`. Use custom events or a shared API instead of selector-based click forwarding.
2. **Badge limited to first item** — `forloop.first` condition means only the first menu item can display a badge. Either expose per-item badge settings or document this limitation in the schema info text.
3. **Promo grid overflow** — The promo block claims 2 columns unconditionally via `--menu-content-columns-desktop: 2`. When combined with featured content, total columns can exceed `grid_columns_count`, causing layout breakage.
4. **Wishlist fallback URL** — Hard-coded `/pages/wishlist` will produce a 404 on stores without that page. Consider hiding the link when `wishlist_page` is blank rather than falling back to a potentially broken URL.
5. **Animation modes bypass underlay sync** — Fade, slide-down, and scale-up modes set `clip-path: none`, which disables the header underlay height animation that provides the shadow/background reveal. The submenu content will appear without the coordinated background transition.
6. **Icon size inconsistency** — Social icons in the top bar use a 16x16 viewBox with hard-coded `stroke-width="1.5"` while mobile bottom nav and wishlist icons use 24x24 with `var(--icon-stroke-width)`. The top bar icons won't respect theme-level stroke width customization.
7. **No accessibility label for badge** — The badge `<span>` has no `aria-label` or `role`, so screen readers will announce "NEW" inline with the link title without context about what it means.

## Mobile bottom nav: DOM-coupled triggers

The `MobileBottomNav` component in `mobile-bottom-nav.js` opens the search and menu drawer by querying the document for specific selectors:

```javascript
openSearch() {
  const searchTrigger = document.querySelector(
    '.search-action button, .search-action a, predictive-search-component button'
  );
  if (searchTrigger) {
    searchTrigger.click();
  }
}

openMenu() {
  const drawerTrigger = document.querySelector(
    '.header__drawer details summary, .header__drawer button, [data-header-drawer-type] summary'
  );
  if (drawerTrigger) {
    drawerTrigger.click();
  }
}
```

If the header drawer switches from `<details>` to a dialog pattern, or if the search component restructures its trigger, the bottom nav silently stops working — a tap that does nothing with no error or feedback. A custom event dispatched on the document (e.g., `theme:open-search`) that the respective components listen for would decouple these.

The component extends `Component` but never calls `super.connectedCallback()` or `super.disconnectedCallback()`. The `on:click` handlers in the Liquid template (`on:click="/openSearch"`) rely on the base `Component` class to wire up event delegation. Given that `HeaderMenu` and `HeaderComponent` both call `super.connectedCallback()`, event binding in `MobileBottomNav` may silently fail.

## Badge scoping mismatch

The badge renders inside the menu item loop but is gated by `forloop.first`:

```liquid
{% if block_settings.show_badge and block_settings.badge_text != blank and forloop.first %}
  <span class="menu-list__badge menu-list__badge--{{ block_settings.badge_style }}">
    {{ block_settings.badge_text }}
  </span>
{% endif %}
```

The schema exposes `show_badge`, `badge_text`, and `badge_style` as block-level settings without any indication that they apply to only the first item. A merchant who enables badges expecting to mark a "Sale" category in the third position will see nothing. Either the schema `info` field should state this limitation, or the implementation should allow targeting specific items (e.g., by index or handle).

## Promo block grid math

In `mega-menu-list.liquid`, the promo block is appended after the `{% case %}` content block:

```liquid
{% if show_promo and promo_image != blank %}
  <span class="mega-menu__content mega-menu__promo-wrapper"
        style="--menu-content-columns-desktop: 2; --menu-content-columns-tablet: 2;">
    {% render 'mega-menu-promo', ... %}
  </span>
{% endif %}
```

This block always claims 2 columns via `grid-column: span var(--menu-content-columns-desktop) / -1`. If a menu also uses `featured_products` (which consumes 2-3 columns), the combined demand could be: menu links (3-4) + featured products (2-3) + promo (2) = 7-9 columns in a 6-column grid. CSS Grid will auto-expand rows, but the visual result is unpredictable.

The promo renders regardless of whether the parent menu item has child links. If a top-level link has no children, no submenu opens and the promo is never visible — a confusing merchant experience.

## Animation modes and the underlay system

The header's mega menu animation is built around a clip-path reveal synchronized with `--full-open-header-height` and `--submenu-height` CSS variables. The underlay elements (`.header__underlay-open`) use these same variables to animate their background gradient height.

The non-default modes override the submenu's clip-path:

```css
header-menu[data-animation='fade'] .menu-list__list-item:where(:not([slot='overflow'])) > .menu-list__submenu {
  clip-path: none;
  opacity: 0;
  transition: opacity var(--submenu-animation-speed) var(--animation-easing), ...;
}
```

With `clip-path: none`, the submenu content occupies full height immediately (just transparent), but the underlay still animates from 0 to full height. Content becomes visible before the background arrives, and the shadow snaps rather than transitions smoothly. The visual choreography between background and content won't match the polished clip-path default.

## Shrink-on-scroll threshold lacks hysteresis

```javascript
if (scrollTop > 50) {
  this.dataset.shrinkState = 'shrunk';
} else {
  this.dataset.shrinkState = 'expanded';
}
```

No dead zone between shrink and expand. Scrolling between 49px and 51px will rapidly toggle the shrink state. The RAF throttling mitigates some jank, but a hysteresis band (e.g., shrink at 60px, expand at 30px) would prevent oscillation when a user stops scrolling near the threshold.

## Top utility bar accessibility

The top bar renders phone and email as bare links with no `aria-label` attributes. When both appear side by side without visual icons or prefixes, screen readers announce raw phone numbers and email addresses without context about their purpose. Adding `aria-label` attributes (e.g., "Call us: 555-1234") would improve comprehension.
